# SLAP FLASH browser OTA review

The site serves the existing 0.1.3 engineering TESTING artifact and recorded SHA-256 from its published GitHub release. No firmware bytes or identity changed. The browser manifest pins an explicitly reviewed package and source identities. Update the manifest and hosted FWSC together when reviewing a newer compatible release.

AQUORA 0.7.38 source at 238a57be426805bbd9292b956315d54a68095bc0 dispatches OTA using ota_service and enters ota_session on the upgrade request only when flash_ok and no AQUORA flash transaction is active. The reviewed flash_ok check requires JEDEC 856014. Its browser updater uses the same two pulls: E0000000 acknowledges staging; the subsequently enumerated loader pulls the full package and F0000000 acknowledges completion. SLAP FLASH requires the exact packaged loader identity ota-FM-1_900 before serving stage two and the exact target identity after reboot.

The package checks validate the 602,112-byte flash image and loader staging bounds. The existing SLAP-5 loader refuses other JEDEC IDs, derives the device chip key and verifies the encrypted app header before writing, and writes application sectors only in [0x4000,0x93000). OTA staging and cleanup use their own sectors. AQUORA's reviewed main and favorite banks are outside the app write window and SLAP-5 song slots. The browser cannot establish the actual bootloader revision from MIDI identity, so the user must confirm compatible V15-style geometry before starting. SLOOP, unknown sources, Open firmware and stock V16 route to M-Flasher. No alternative chip revision is enabled.

Node tests cover the exact package, bad SHA-256, corrupt UFW, wrong identity, bad request range, ambiguous MIDI devices, the reviewed source list, temporary half-enumeration, staged migration and reboot, unsupported loader, transfer disconnection and wrong post-restart identity. These are software simulations. First migration on physical hardware remains a TESTING step.
